# 异常处理（failure-handling）

遇到异常时**先定位原因，再决定处置**；不静默失败、不补造数据、不把无法判断写成事实。任何异常都要写进 `result.json` 的 `status` 与 `uncertainty`，并说明可人工接管的位置。

## 文字层缺失 / 扫描件

- 检测：PDF 文本提取为空或几乎为乱码。
- 处置：改用 OCR；对低置信区域标注置信度；翻译后对应处写 `[待人工确认: OCR 不确定]`。
- 不把 OCR 噪声当作原文；明显缺字处写 `[原文缺失]`。

## 公式 / 表格为图片

- 处置：保留原图位置（引用原图路径或页码），只抄录**可见且确定**的内容；不确定的符号写 `[待人工确认: 公式/表格为图片]`。
- 不猜测公式内容，不伪造 LaTeX。

## 参考文献无法解析

- 处置：只翻译标题/摘要等可读部分；作者名、年份、期刊、卷期页、DOI 保留原文；不重编号、不增删条目。
- 若整段参考文献无法识别边界，标注并跳过，说明原因。

## 原文残缺 / 语言混杂

- 处置：明确写出残缺位置与范围；缺失部分写 `[原文缺失]`，不补造。
- 中英混杂或含第三种语言：逐段标注语言，按目标语言翻译可译部分，不可译部分保留原文并注明。

## 材料缺失 / 路径失效

- 处置：列出实际存在的文件；若 `case.json` 指定的材料不存在，写明"缺失"与尝试过的路径，**不**用其它文件冒充。
- 若只有 `task.md` 无 `case.json`，从 `task.md` 推断范围与输出字段，并在 `sources` 记录推断依据。

## 任务范围过大 / 资源受限

- 处置：优先交付明确范围内的最小可用成果；写清"已完成"与"未完成"边界；分多次保存中间产物。
- 诚实标注部分完成（`status: partial`），不把未完成部分写成已完成。

## 多版本 / 冲突材料

- 处置：以 `case.json` 指定的材料为事实依据；发现版本冲突时记录差异并说明选择了哪一个、为什么。

## 运行失败

- 处置：记录失败命令/工具、错误信息、尝试过的替代方案；给出可人工接管的位置。不要无依据地反复重试同一策略超过两次。
